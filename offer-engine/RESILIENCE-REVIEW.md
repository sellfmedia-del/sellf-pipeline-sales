# Offer-engine resilience review

## Scope

- Logo: Flash → Argon for transient HTTP 500/502/503/504, timed-out or failed model transport, invalid model output, and recoverable historical records. A shared 220-second deadline bounds both logo stages. Uncertain reservations are kept; completed outputs are reused. If cleanup is unavailable or unsafe, preserve the validated original upload, sign it, visibly explain the change and require visual approval. Invalid uploads and unauthorized requests remain rejected.
- BHS: Pro → Argon (or Argon → Pro when Argon was primary). The request contract, methodology and existing token envelope are retained. A lower-cost alternate can be checked before a paid primary call if the primary's upper quote cannot fit the remaining budget. This is not an automatic refund or budget reset.
- Accounting: successful responses with fully verified usage settle the measured cost even when JSON/finish status is unusable. Their rejected content cannot reach the next stage and the same paid call is never replayed. Unknown HTTP/transport outcomes retain their conservative reservation.
- Budget: retain the same durable 50 TRY cap and attempt/total counter separation. Reserve at least 25 TRY of remaining capacity for downstream research before new paid logo/planning model calls. This is a conservative capacity floor, not proof that every possible report/failure combination will fit. The 20–30 TRY range remains a target, not a guaranteed invoice. The current tariff validity guard remains unchanged.
- Sources: URL and literal quote must occur in the server's read packet or clearly labelled search snippets. Invalid citations, unsupported numeric tokens, unsupported findings and benchmarks are excluded from customer transfer; missing data stays unavailable/null. The same checks apply before scope selection. A rejected synthesis gets one alternate; if the alternate is unavailable/budget-limited, only the server-filtered partial projection can be returned, clearly marked incomplete. The rejected model document is never the fallback.
- Reuse: retain immutable paid records. Retrieve available historical evidence on the same authenticated card before projecting reused findings. A legacy document with no read evidence cannot authorize factual claims; its raw paid record is preserved internally and is not invented into proof.
- Pricing: existing catalogue, segment columns, floors, margins, currency and manual-price rules remain in charge. Scope-provider outages use the explicit brief-derived fallback, retaining every recognized requested service instead of truncating to three. The proposal intro rejects numeric claims; existing generic copy is used when necessary.

## Verification

Regression tests cover both-model outages, historical timeouts, duplicate/concurrent claims, exhausted budgets, the incident's 30,469-token synthesis and 33.95 TRY balance, source injection, unmatched/disjoint quotes, numeric substrings/signs, missing evidence, source-only partial projections, changed briefs, signature tampering, unchanged deterministic prices and signed proposal assembly.

A controlled API integration test exercises source-plan fallback, scope-model timeout/outage, signed original-logo recovery, source-checked BHS, two exact monthly alternatives and the proposal's existing sections without external paid calls. Browser-component tests exercise the original fallback notice and mandatory visual review. Full desktop/browser launching is blocked by this local environment's socket policy; do not count that attempted run as passing. Preview build results are recorded in the PR. The explicit `node offer-engine/scripts/qa-browser.mjs` entry point also builds fixtures and runs the full suite with the pinned packaged Chromium; a separate QA branch may invoke it without altering production build settings. Real paid model output quality and live authenticated sales-user behavior require a controlled acceptance run; fixture tests do not establish them.

## Limits and rollback

A quote match establishes provenance, not the source's truth or semantic entailment of every interpretation. Inferences, periods and company/market suitability still require review. Unknown metrics stay unknown. A global outage, account/quota/auth issue, expired tariff or exhausted historical budget can still prevent a full new AI analysis; do not promise that no error can ever occur. No bound is raised, reservation erased or paid POST blindly replayed to disguise that condition. Partial research and original-image substitution must not be presented as a completed full analysis or a cleaned logo.

No database/schema, auth/RLS, environment or production configuration changes. Production requires approval of the Preview. Rollback is a revert of this PR followed by deployment; existing stored records and charges are retained. Refresh an in-progress browser session after rollback so its proof/schema version is recalculated by the active API.
