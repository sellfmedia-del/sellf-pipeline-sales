# BHS expert evidence v6 — preview review

Approved scope: new public-source BHS research only. Keep pricing, selected costs,
monthly/standard offers, logos, template, existing records and production data.

## Behavior

- Existing signed v3/v4/v5 jobs retain their original stage keys and contracts.
  New jobs use isolated v6 stage keys; completed old research is not rewritten.
- Read brand identity before discovery. Candidate domains are not evidence;
  partial competitor plans can continue honestly rather than inventing peers.
- Six initial methodology searches plus up to six focused followups stay within
  the existing fourteen-search ceiling (including two discovery searches).
  Existing DNS/SSRF/public-reader safeguards, 24-source cap and bounded browser
  rendering remain. Seeded reads are reused; v6 limits reader concurrency to four.
  The first pass retains at most 16 sources, leaving eight slots for followups.
  Verified publisher redirects and already-read product paragraphs preserve
  appropriate peers without accepting an unrelated same-name business.
  Read pages and unread search snippets use the same identity filter; six
  methodology queries are anchored to the full exact brand name. Raw search
  receipts remain in the existing paid records.
- BHS v6 uses Gemini 2.5 Pro with Gemini 3.1 Pro as its bounded alternate.
  The primary synthesis has at most 160 seconds within the same 250-second
  recovery window, leaving time for an alternate. Other engines and signed
  legacy jobs keep their original provider paths. No tariff or cap changes.
- One Pro synthesis returns compact findings, peer/score references and all 24
  area statuses. Repeated paragraph text is transported once, with one visible
  ID per complete paragraph; all original proof chunks remain server-side.
  No source fact is omitted by this compression. Server binds short immutable IDs to read quotes, constructs
  the same six dimensions and nine report sections, and computes weighted totals.
- Markdown link labels retain provenance through the existing canonical-card
  verifier against original read segments; fabricated cleaned quotes still fail.
  Peer URLs bind to verified final hosts so www redirects do not discard peers.
  Scores also require a nonempty band reason.
- Short proof IDs preserve the adjacent chunks of the same bounded paragraph,
  so the evidence view does not cut off a supporting sentence. Numeric counts
  also require the same unit: dates cannot become review counts or time slots
  port counts. Platform hints cannot imply speed or cost advantages.
- Findings contain observation, commercial hypothesis, limitation and question.
  Local guards address reviewed failure classes; they are not a general semantic
  truth guarantee. Current-model instructions, citations and human comparison
  remain necessary. No separate paid reviewer or additional provider is added.
- The existing proposal scope/copy stage is unchanged, including its model
  request and fallback rules. v6 dispatch covers BHS research only; the original
  scope path is shared with v5. A regression compares both requests/results.
  Services and project costs remain explicit user selections.
- The synthesis envelope is 16,384 maximum / 12,288 minimum tokens, compared with
  the old Pro envelope of 32,768 / 24,576. The six dimensions, 24 areas and nine
  sections remain; repetitive report/source text is projected by the server.
- Existing 30 TRY normal target / 50 TRY hard cap, accounting, uncertain receipts,
  recovery and zero-cost continuation remain. Empty compact model documents
  now fail inside the existing bounded fallback, before an empty BHS can be signed. Factual quotes are necessary but
  do not independently prove identity, causal claims or actual commercial impact.

## Validation

Existing legacy-handler tests explicitly pin v5, so they still exercise frozen
paid jobs rather than silently changing fixture semantics. New expert tests
cover default v6, old signed jobs, compact proof binding, snapshots, partial
plans, no-repeat reads, capped search/model calls, and the reviewed semantic
failure classes. Full test/build results are recorded in the PR. Shared findings can support
several methodology areas without generating duplicate findings. Neutralized
technical proxies cannot reappear as critical risks. The v6 response omits
redundant originalReport copies; all findings, quotes and source references
remain in the response and immutable paid stage records.

Local verification: 54 root tests + 359 engine tests passed (21 opt-in
checks skipped), focused ESLint/module parsing and production build passed.
Ten desktop/mobile browser tests passed for BHS continuation, both currencies,
explicit costs, monthly variants, stored offers and both proposal languages.
No non-BHS production source, build script, config or dependency differs from main.

A five-public-brand batch and a separate forced-primary-503 Humm acceptance
are reviewed separately; build success alone is not quality acceptance.
The forced 503 was a QA fixture. Its alternate call entered the unchanged cap
but did not complete. That failure remains a release blocker, not a passing
BHS. The final focused Humm run has no injected failure.

Public-brand acceptance is restricted to the Pipeline project's preview build,
the exact feature branch, a dated commit marker and an expiry. It runs a single focused
public brand with independent in-memory ledgers and no database writes, email
or publishing. Paid calls cover BHS only; the unchanged proposal scope stage
uses its existing fixture in this QA, with separate equality/browser tests. Each retains the same 50 TRY cap. Generated QA output is removed
by the BHS test on every ordinary build and never generated in production.
The shared build script is byte-identical to main; no project settings change.
